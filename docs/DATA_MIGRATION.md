# Life 数据迁移契约

## 当前格式

- 发行包：`@amadeus/life@1.2.0`
- 持久 Schema Version：SQLite `meta.schema_version = 10` (`src/model.js`)
- 数据范围：`databasePath` 指向的独立 SQLite/WAL/SHM（默认 `$DSH_HOME/amadeus-life/life.sqlite`），以及 DSH Profile 中的 Workspace、唤醒和 Provider 配置。
- 本轮迁移：1.1.0 → 1.2.0 不改变 schema。既有 v2–v9 增量迁移只在健康旧库上运行；未知/损坏 schema 拒绝使用而不创建空库。

## 未来迁移流程

读取并验证当前版本、完整性和关键关联。未知或未来版本拒绝写入，并给出可读的迁移路径提示。现有数据先创建一致性备份；备份失败即停止。每一步迁移使用事务或原子文件替换，幂等且可重试；内容和引用复核通过后才标记新版本。不能通过删除数据库、清空配置或重新建立 Session 来“修复”错误。

备份必须位于独立用户数据目录，记录时间、原 Schema Version、目标版本和校验值，不能进入发行包或 Git。恢复时区分：只回滚代码、只恢复配置、完整恢复数据库和 Profile。任何不可逆转换都必须保留升级前快照；旧程序如不支持新格式，必须连同旧数据快照恢复。

## v1.2.0 验证清单

- 使用 `1.1.0` 的合成数据，核对升级前后字段内容、关联和权限，而不只比较条数。
- 停用/启用和硬重启后重新读取。
- 令备份或迁移失败，确认旧数据仍完整且错误可见。
- 使用与上一版本匹配的备份演练回滚；不把新版本数据库直接交给旧程序。
- 验证：Persona 身份、意图、活动事件、唤醒规则、预算、Workspace 绑定、未知活动对账和重启恢复。

未在真实 DSH Desktop/Market 运行的项目不得在发行报告里记作通过。
