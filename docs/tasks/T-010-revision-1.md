# T-010 revision 1 — concrete Codex review

The first implementation passes Codex's independent `node --test test/life-core.test.js` (20/20), but is NOT accepted yet. Same Creator session, same repository, no children/web/profile mutations/commits. Budget: up to 25 model steps, 10 minutes. Inspect only these relevant paths and fix the following, with deterministic regressions and exact results:

1. `src/core.js requestCancelActivity` currently maps `unknown` to `cancelled` immediately and `transitionActivity` accepts `stopping -> cancelled` without confirmation evidence. Unknown external work may still run. A cancellation request for uncertain/external running or paused work must remain stopping/unknown pending explicit confirmation; terminal cancellation must require supporting evidence from a trusted service/provider boundary. Model tool args/note alone must not self-assert an external stop. Do not turn an unknown task into success. Keep safe pre-start local pending cancellation usable. Add regressions for unknown + external paused cancellation, direct confirmation bypass, and late completion. Be clear in docs which operations are local records versus trusted provider acknowledgement; no real external provider is installed.

2. `src/index.js` always calls `core.markInterruptedAsUnknown()` at activation. A second live plugin instance pointed at the same DB can therefore poison the first owner's running activities. Add a small explicit single-runtime ownership guard/lease for adapters (not a new job/agent framework) before recovery; fail the second adapter closed with explicit health, preserve the first owner's activities, release ownership only for the owning instance on disposal, and support safe stale-owner recovery after actual process death. Core independent connections for atomic due claiming must remain possible. A PID that is alive/ambiguous must not be treated as dead. Test two live adapters plus release/reopen; no broad filesystem delete.

3. `core.tick` payload currently contains description; adapter broadcasts the full event on a host-wide bus. Publish reference-only event envelopes without intent descriptions/raw content. Authorized getIntent can load description separately. `life_health` currently returns global counts + host databasePath without session scope; model-facing health should expose only general health and that caller's scoped counts, not database paths or another session's activity metadata. Trusted Host getHealth may retain diagnostic details. Add privacy regressions with a second session scope.

4. T07 currently calls two independent connections sequentially. Keep it and add a real concurrent test using worker_threads or bounded subprocess peers synchronized at a barrier over the same already-initialized SQLite store. Exactly one valid reconsideration event must be produced in total. Use synthetic data, bounded cleanup and no long sleeps. Codex can run this outside your shell sandbox if spawn is denied; report that honestly.

5. On setup errors after opening the store (e.g. duplicate service or tool registration failure), the adapter must close SQLite and release its ownership guard. Register lifecycle cleanup before publishing service/tools, and test a setup failure; do not leave a timer/lease open. Keep other host capabilities usable.

Keep the implementation small, no unrelated refactor or new external dependencies. Preserve T01-T14 and the shared M0 contract snapshots. Update the ADR/README/HANDOFF to describe actual semantics and not-run DSH loading. Creator/model/high are already independently verified by Codex, not something you need to rediscover.
